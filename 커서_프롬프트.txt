너는 서비스 기획과 UI/UX 설계에 능숙한 웹 개발자야. 아래 요구사항을 바탕으로 실제로 실행하고 테스트할 수 있는 모바일 중심 웹 서비스 'OOS' 를 만들어줘.
단순한 소개 페이지나 화면 시안이 아니라, 사용자가 버튼을 누르고 상황을 선택하며 응대 문장을 확인할 수 있는 작동하는 초기 제품이 필요해.
나는 개발 초보자이므로 합리적인 기술적 선택은 네가 해주고, 실행 방법과 수정 방법은 쉬운 한국어로 설명해줘. 기존 프로젝트가 있다면 구조를 먼저 확인하고 활용하되, 기존 작업을 임의로 삭제하거나 전면 교체하지 마.

1. 서비스 소개와 핵심 목표
서비스 이름은 OOS, Only One Sentence야.

핵심 의미는 "매 순간 필요한 다음 한 문장" 이야.

외국인 손님을 응대하는 직원이 영어 때문에 당황했을 때, 지금 말해야 할 문장과 손님의 대답 이후 대응을 빠르게 찾도록 돕는 서비스야.

주요 사용자는 카페·편의점·식당·PC방의 영어 초보 아르바이트생과 신입 직원이야.

일반적인 번역기나 영어 학습 앱과 달리, 사용자가 한국어 문장을 길게 입력하는 대신 상황을 선택하고 다음 행동을 안내받는 방식으로 만들어줘.

가장 중요한 목표는 다음과 같아.

- 홈 화면에서 상황에 맞는 첫 응대 문장까지 빠르게 도달하기
- 첫 문장 이후에도 대화가 이어지도록 돕기
- 예상하지 못한 답변에는 되묻기나 담당자 확인으로 연결하기
- 근무 중 응대 기능과 근무 전후 연습 기능을 분리하기

'5초 이내 문장 도달'은 설계 목표이지 검증된 성과는 아니야. 이미 달성한 것처럼 홍보 문구를 작성하지 마.

2. 첫 사용과 기본 화면 구조
회원가입이나 로그인 없이 사용할 수 있게 해줘.(후에 변경 가능)

첫 방문에는 짧은 소개와 함께 근무 업종을 선택하게 해줘.
- 카페
- 편의점
- 식당
- PC방

선택한 업종은 이 기기에 저장하고, 다음 방문에는 해당 업종의 근무 홈으로 바로 진입하게 해줘. 설정에서 언제든 변경할 수 있어야 해.

하단 메뉴는 다음처럼 단순하게 구성해줘.(후에 변경 가능)
- 근무
- 나의 표현
- 연습
- 설정

근무 화면에는 공통 응대와 선택 업종의 상황만 보여줘. 다른 업종의 카드까지 한 화면에 섞지 마.

3. 근무 홈 화면
홈 화면의 우선순위는 다음과 같아.

1. 현재 업종 표시와 변경 진입점
2. 눈에 잘 보이는 '못 알아들었어요' 버튼
3. 공통 응대 상황
4. 내 업종 전용 상황
5. 최근 사용한 표현과 즐겨찾기로 가는 간단한 진입점

'못 알아들었어요' 기능은 홈뿐 아니라 모든 응대 단계에서 접근 가능하게 해줘.

상황 버튼에는 한국어 제목과 직관적인 아이콘을 넣어줘. 영어 문장을 아직 모르는 사람도 어떤 상황인지 알 수 있어야 해.

근무 중에는 퀴즈, 포인트, 학습 독려 팝업, 불필요한 애니메이션을 보여주지 마.

4. 구현할 상황 범위
총 13개 상황 묶음을 구현해줘. 문장 13개만 보여주는 것이 아니라, 각 상황에 맞는 짧은 대화 흐름이 있어야 해.
1)공통 상황 5개
- 되묻기·이해 확인
- 잠시 대기·담당자 확인
- 결제 오류·다른 결제 수단 확인
- 상품·서비스 이용 불가와 대안 제안
- 취소·교환·환불 요청을 받고 처리 가능 여부 확인
2) 카페 전용 2개
- 음료 옵션 확인
- 매장 이용·포장 확인
3) 편의점 전용 2개
- 상품 위치 안내
- 행사 적용 여부 확인
4) 식당 전용 2개
- 인원·좌석·대기 안내
- 주문 내용·요청사항 확인
5) PC방 전용 2개
- 좌석·이용 시작 안내
- 이용 시간·요금 확인

공통 상황은 구조를 재사용하되, 업종에 맞는 문장과 후속 안내를 제공해줘. 예를 들어 카페의 음료 품절과 PC방의 좌석 이용 불가를 똑같은 문장으로 처리하면 안 돼.

모든 업종에서 환불·교환이 같은 방식으로 가능하다고 가정하지 마.

5. 상황별 응대 화면과 대화 흐름
상황을 선택하면 지금 직원이 말할 영어 한 문장을 가장 크게 보여줘. 아래에는 한국어 뜻을 표시해줘.
기본 기능은 다음과 같아.
- 발음 듣기
- 즐겨찾기 추가·해제
- 손님에게 크게 보여주기
- 못 알아들었어요
- 이전 단계
- 처음으로
- 이 상황을 연습용으로 저장

기본 상황은 2~3단계 정도로 구성하되, 억지로 단계를 늘리지 마.

직원의 문장 다음에는 손님의 예상 답변을 뜻 중심 선택지로 보여줘.

예를 들어 다음과 같아.
- 다른 상품이나 메뉴를 원해요.
- 기다릴 수 있다는 뜻이에요.
- 취소하고 싶다는 뜻이에요.
- 무슨 뜻인지 모르겠어요.

각 선택지에는 해당 의미의 영어 예시도 함께 보여줘.
* 중요: 이 선택지는 직원이 손님의 말을 듣고 직접 고르는 기능이야. 손님의 말을 자동으로 듣거나 분석했다고 표현하지 마.

'뜻을 모르겠어요'를 선택하면 다시 말해 달라는 요청이나 담당자에게 확인하는 경로로 연결해줘. 예상 답변에 억지로 끼워 맞추지 않도록 해줘.

각 분기 끝에는 '응대 마침', '추가 확인 필요'처럼 다음 상태가 명확하게 표시되게 해줘. 담당자 확인 버튼은 안내 문장을 보여주는 기능이며, 실제로 점장에게 연락했다고 표시하면 안 돼.

6. 영어 콘텐츠 작성 원칙
초기 영어 표현과 대화 흐름도 직접 작성해줘.

- 짧고 자연스러운 영어
- 서비스 현장에 맞는 정중한 표현
- 한국어 뜻 함께 제공
- 업종과 실제 상황에 맞는 내용
- 복잡한 문법과 불필요하게 긴 설명 지양

단, 이 콘텐츠는 검수 전 초안이야. 실제 전문가가 검수했다고 표시하지 마. 설정이나 서비스 안내에서 시제품 콘텐츠라는 사실을 확인할 수 있게 해줘.

요금·대기 시간·행사 조건·재고·좌석 상태는 임의로 만들지 마.

구체적인 값이 필요한 문장은 직원이 값을 입력하거나 확인한 뒤 사용할 수 있게 해줘. 값이 없으면 '확인 후 안내하겠습니다'처럼 안전한 문장으로 연결해줘.

미입력 표시나 대괄호가 남은 문장을 손님 화면에 보여주거나 음성으로 읽지 마.

7. 손님에게 보여주는 화면과 발음 듣기
'크게 보여주기'를 누르면 영어 문장을 큰 글씨로 보여주는 별도 화면이나 전체 화면을 열어줘.

- 직원용 한국어 설명과 조작 요소는 최소화
- 닫기 버튼은 명확하게 표시
- 필요한 경우 손님이 고를 수 있는 영어 선택지 제공
- 원래 응대 단계로 돌아갈 수 있게 구현

발음 듣기는 가능한 경우 브라우저의 영어 음성 읽기 기능을 활용해줘.

지원하지 않는 기기나 재생 실패 상황에서는 안내를 보여줘. 페이지 진입 시 자동으로 소리를 재생하지 말고, 사용자가 버튼을 눌렀을 때만 재생해줘.

8. 나의 표현과 기록
다음 내용을 기기에 저장해줘.
- 선택 업종
- 즐겨찾기한 표현
- 최근 사용한 표현
- 연습하려고 저장한 상황

새로고침이나 재방문 후에도 유지되게 해줘.

업종을 변경해도 기존 즐겨찾기를 임의로 삭제하지 말고, 업종 표시나 필터로 구분해줘. 같은 표현이 중복 저장되지 않게 해줘.

저장된 항목이 없을 때는 자연스러운 빈 화면 안내를 보여줘.

손님 음성, 실제 대화 원문, 결제정보는 수집하지 마. 설정에서 저장 기록을 초기화할 수 있게 하되, 삭제 전에는 확인을 받아줘.

9. 연습 모드와 AI 활용
연습 모드는 실제 근무 화면과 분리해줘.
사용자가 저장한 상황을 선택하면, 손님 역할의 질문에 짧은 영어로 답하고 피드백을 받는 약 3분 분량의 역할극을 할 수 있도록 해줘.
초기 구현은 텍스트 입력 방식으로 충분해. 음성 인식은 넣지 마.
최소한 카페의 '품절 후 대안 제안' 상황 하나는 끝까지 연습할 수 있게 만들어줘.

AI는 다음 역할에 사용해줘.
- 같은 상황에서 손님의 답변을 다양하게 바꾸기
- 사용자의 답변이 상황에 적절한지 짧게 설명하기
- 더 간단하고 자연스러운 표현 제안하기

매장 정책이나 재고를 AI가 결정하게 하지 마. 연습 화면에 '가상의 연습 상황'임을 표시하고, 연습 결과가 실제 매장 규칙은 아니라는 점을 안내해줘.

* 외부 AI 연결이 아직 없는 경우:
- 고정 대화로 작동하는 연습 데모를 제공해줘.
- 화면에 '연습 데모 — 실제 AI 미연결'이라고 명확히 표시해줘.
- 사용자의 자유 답변을 실제로 평가하지 못한다면, 평가했다고 꾸미지 말고 예시 답변을 보여줘.
- 실제 AI를 연결할 부분은 분리해서 나중에 교체하기 쉽게 만들어줘.

AI를 연결한다면 API 키는 서버에서만 관리하고, 브라우저 코드나 저장소에 노출하지 마. 오류·응답 지연 시 안내와 재시도를 제공하고, AI 장애가 기본 응대 기능에 영향을 주지 않게 해줘.

10. 디자인 방향
- 공부 앱보다 근무 중 바로 사용하는 도구처럼 보여야 해.
- 모바일 우선의 반응형 화면
- 아이보리~크림 계열색의 배경과 짙은 고동색~검정색 글자
- 포인트 색상은 청록색 계열
- 큰 버튼과 넉넉한 터치 영역
- 한 손으로 조작하기 편한 배치
- 한국어 중심 탐색, 영어 중심 응대 카드
- 작은 화면에서도 잘리지 않는 문장
- 색상만으로 상태를 구분하지 않는 구성

과도한 장식, 거대한 소개 배너, 캐릭터, 게임 요소는 넣지 마.

현재 상황과 다음 행동을 쉽게 파악할 수 있게 해줘. 상황 버튼의 순서가 사용 때마다 임의로 바뀌지 않게 해줘.

11. 안전과 초기 범위 제한

다음 원칙을 반드시 지켜줘.

- 알레르기·성분의 안전 여부를 추측하지 않기
- 환불·할인 가능 여부를 임의로 보장하지 않기
- PC방 요금·잔여 시간·계정 조건을 만들어내지 않기
- 비밀번호나 결제정보를 입력받지 않기
- 재고·POS·담당자 연락 기능이 연결된 것처럼 꾸미지 않기
- 실제 측정하지 않은 사용 통계나 성과를 표시하지 않기

이번 버전에서는 회원가입, 유료 결제, 점주 관리자 화면, POS 연동, 다국어 확장, 포인트 제도, 본격적인 단어장, 실시간 음성 자동 분기, PC방 기기 오류 해결은 제외해줘.

12. 개발 방식과 완료 기준

우선 기존 프로젝트를 확인하고 간단한 구현 계획을 세운 뒤, 계획만 설명하고 끝내지 말고 실제 구현을 진행해줘.

개발 순서는 다음과 같이 해줘.

1. 업종 선택과 근무 홈
2. 공통 응대와 대화 분기
3. 네 업종 전용 상황
4. 즐겨찾기·최근 사용·저장 기능
5. 큰 글씨 화면과 발음 듣기
6. 연습 데모와 AI 연결 구조
7. 모바일 화면과 오류 상태 점검

문장·상황 데이터는 화면 구성과 분리해서, 나중에 내가 쉽게 수정하고 업종을 추가할 수 있게 해줘.

완료 전에는 가능한 범위에서 다음을 실제로 확인해줘.

- 네 업종 모두 선택·변경 가능
- 홈에 공통 상황과 선택 업종 상황만 표시
- 모든 상황에 작동하는 응대 경로 존재
- 예상 답변 선택 시 다음 문장으로 이동
- 모든 단계에서 되묻기·안전한 확인 경로 접근 가능
- 뒤로 가기·처음으로 이동 정상 작동
- 즐겨찾기와 업종 설정이 새로고침 후 유지
- 미입력 값이 있는 문장을 손님에게 보여주지 않음
- AI 미연결·오류 상태가 명확하게 표시
- 모바일에서 버튼이나 문장이 잘리지 않음

마지막에는 실행 방법, 구현한 기능, 미완성 기능, 실제 AI 연결에 필요한 설정, 직접 테스트할 순서를 쉬운 한국어로 정리해줘. 테스트하지 못한 항목은 확인했다고 주장하지 말고 별도로 알려줘.

가장 중요한 것은 예쁜 화면만 만드는 것이 아니라, 외국인 손님 앞에서 당황한 직원이 실제로 다음 한 문장을 찾아 사용할 수 있는 흐름을 완성하는 것이야.
